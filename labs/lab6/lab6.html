Lab 6: SPI and the Internet of Things

Joaquin Gonzalez-Salgado | jgonzalezsalgado@hmc.edu | October 12, 2026

Introduction

In this lab, an internet-accessible IoT device was built around the STM32L432KC MCU, a DS1722 digital temperature sensor, and an ESP8266 WiFi module. The MCU communicates with the DS1722 over a custom SPI driver written directly against the CMSIS device templates (no third-party drivers), and with the ESP8266 over UART to host a webpage. The page lets a user view the current ambient temperature, toggle an external LED, and, for the excellence requirement, select the DS1722’s conversion resolution (8 through 12 bits) directly from the browser.

Design and Testing Methodology

ESP8266 UART Protocol and Web Server

The ESP8266 is connected to the MCU over USART1 at 125,000 baud. Each time a browser loads the page, the ESP8266 sends the MCU a short request that names what the user clicked, ending in a newline. The main loop reads the request one character at a time until that newline arrives, then checks it for a known tag: ledon or ledoff sets the LED, and res8 through res12 changes the DS1722’s resolution. Once the request has been handled, the temperature is read from the DS1722 over SPI and the webpage is sent back to the ESP8266 over the same UART.

Figure 1 shows the wiring between the Nucleo-L432KC and the DS1722. The SPI clock is on PA5, PB4 is the MCU’s data input (MISO) and PB5 is the MCU’s data output (MOSI), and the chip enable is on PB0. The DS1722 is powered from the Nucleo’s +5V pin on both VDDD and VDDA and shares a common ground with the MCU. SERMODE is tied to +5V, which selects the SPI interface instead of the 3-wire interface. The ESP8266 WiFi click module is not shown, as it was connected on the motherboard.

Oscilloscope Trace

Lab 6 SPI Oscilloscope Trace // Joaquin Gonzalez-Salgado // October 12, 2026

NoteExpand to see Oscilloscope Trace

Figure 2 shows a full SPI read transaction captured on an oscilloscope, since no logic analyzer was available. Channel 4 (pink) is CE, which goes high at the start of the transaction and low at the end, as expected for the DS1722’s active-high chip enable. Channel 3 (blue) is SCLK, which idles low and produces 16 clock pulses: 8 for the address byte and 8 for the data byte. Channel 1 (yellow) is the data from the MCU to the sensor, which carries the register address during the first byte, and channel 2 (green) is the data from the sensor back to the MCU, which carries the temperature reading during the second byte. The 16 clock pulses span about 12.8 µs, matching the 1.25 MHz SPI clock.

Results and Discussion

NoteResults and Discussion

The design was a success!

The design met all specifications. The webpage displays the current temperature read from the DS1722 and updates it when refreshed, shows the LED state and can toggle it, and lets the user select the sensor’s resolution from 8 to 12 bits.

Conclusion

This lab combined a from-scratch SPI driver for the DS1722 temperature sensor with a UART-based request/response protocol to the ESP8266, producing a webpage that reads live temperature, controls an LED, and changes the sensor’s resolution over WiFi. The active-high CE of the DS1722, formatting the temperature without floating-point printf, and handling the stale reading after a resolution change were the main departures from a “textbook” SPI/UART implementation.

Prompt: I’m writing a bare-metal SPI driver for a DS1722 temperature sensor on the STM32L432KC using CMSIS, no HAL. The DS1722’s chip-enable line is active HIGH instead of the usual active-low chip select. How should that change my SPI transaction code compared to a normal active-low peripheral?

NoteGenerated Code: 
// Active-HIGH CE: assert CE HIGH to start, LOW to end — opposite of
// a normal active-low SPI chip select.

#define DS1722_WRITE_BIT 0x80

void ds1722_write_reg(uint8_t reg, uint8_t data) {
    digitalWrite(SPI_CE, PIO_HIGH);   // assert (opposite of CS-low parts)
    spiSendReceive(reg | DS1722_WRITE_BIT);
    spiSendReceive(data);
    digitalWrite(SPI_CE, PIO_LOW);    // deassert
}

uint16_t ds1722_read_temp_raw(void) {
    digitalWrite(SPI_CE, PIO_HIGH);
    spiSendReceive(0x01);             // LSB register address, read
    uint8_t lsb = spiSendReceive(0x00);
    uint8_t msb = spiSendReceive(0x00); // auto-increments to MSB reg
    digitalWrite(SPI_CE, PIO_LOW);
    return (msb << 8) | lsb;
}

Reflection:

This week is Claude Sonnet again. Its core advice was correct: since CE is active-high, every transaction simply swaps which level means “asserted,” so the GPIO write at the start of a transaction drives CE high instead of low, and the one at the end drives it low instead of high. Everything else about clocking bytes out over SPI stays the same. It also suggested reading the LSB and MSB registers back-to-back in one CE-asserted burst to take advantage of the DS1722’s register auto-increment, rather than doing two separate transactions.

Where it fell short was the temperature decode itself: it returned the raw register pair as a plain uint16_t and left interpreting the sign and fractional bits as an exercise, without mentioning that the MSB is signed two’s-complement or that the LSB’s upper nibble holds the fractional bits, worth 1/2 down to 1/16 of a degree. That part, including the negative-temperature edge case (-10.5 °C is stored as MSB = 0xF5 and LSB = 0x80), had to be worked out by hand from the datasheet.

#include "stm32l432xx.h"
#include <stdint.h>
#include <stdbool.h>

// =============================================
// DS1722 DEFINITIONS
// =============================================

#define DS1722_SPI          SPI1

#define DS1722_CE_HIGH()    (GPIOA->BSRR = (1U << 4))
#define DS1722_CE_LOW()     (GPIOA->BSRR = (1U << (4 + 16)))

#define DS1722_READ_TEMP_LSB    0x01U
#define DS1722_WRITE_CONFIG     0x80U

// 12-bit resolution, continuous conversion mode
#define DS1722_CONFIG_12BIT     0x40U

#define SPI_TIMEOUT             100000U


// =============================================
// SMALL TIMING DELAY
// =============================================

static void DS1722_Delay(void)
{
    for (volatile uint32_t i = 0; i < 50U; i++)
    {
        __NOP();
    }
}


// =============================================
// SPI1 INITIALIZATION
// =============================================

void DS1722_SPI_Init(void)
{
    // Enable GPIOA and SPI1 clocks
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB2ENR |= RCC_APB2ENR_SPI1EN;

    // PA4: GPIO output (CE)
    // PA5, PA6, PA7: Alternate function (SPI1)

    GPIOA->MODER &= ~(
        (3U << (4U * 2U)) |
        (3U << (5U * 2U)) |
        (3U << (6U * 2U)) |
        (3U << (7U * 2U))
    );

    GPIOA->MODER |=
        (1U << (4U * 2U)) |
        (2U << (5U * 2U)) |
        (2U << (6U * 2U)) |
        (2U << (7U * 2U));

    // Configure PA5, PA6, PA7 for AF5 (SPI1)
    GPIOA->AFR[0] &= ~(
        (0xFU << (5U * 4U)) |
        (0xFU << (6U * 4U)) |
        (0xFU << (7U * 4U))
    );

    GPIOA->AFR[0] |=
        (5U << (5U * 4U)) |
        (5U << (6U * 4U)) |
        (5U << (7U * 4U));

    // Configure GPIO output speed
    GPIOA->OSPEEDR |=
        (3U << (4U * 2U)) |
        (3U << (5U * 2U)) |
        (3U << (6U * 2U)) |
        (3U << (7U * 2U));

    // No pull-up or pull-down
    GPIOA->PUPDR &= ~(
        (3U << (4U * 2U)) |
        (3U << (5U * 2U)) |
        (3U << (6U * 2U)) |
        (3U << (7U * 2U))
    );

    // CE initially LOW (inactive)
    DS1722_CE_LOW();

    // Disable SPI before configuring
    DS1722_SPI->CR1 = 0U;
    DS1722_SPI->CR2 = 0U;

    // Configure SPI:
    // Master mode
    // CPOL = 0
    // CPHA = 1 (SPI Mode 1)
    // Software NSS management
    // Baud rate = PCLK2 / 32

    DS1722_SPI->CR1 =
        SPI_CR1_MSTR |
        SPI_CR1_CPHA |
        SPI_CR1_SSM |
        SPI_CR1_SSI |
        SPI_CR1_BR_2;

    // 8-bit data size and 8-bit RX FIFO threshold
    DS1722_SPI->CR2 =
        (7U << 8U) |
        (1U << 12U);

    // Enable SPI
    DS1722_SPI->CR1 |= SPI_CR1_SPE;
}


// =============================================
// SPI BYTE TRANSFER
// =============================================

static bool DS1722_SPI_Transfer(
    uint8_t tx_data,
    uint8_t *rx_data
)
{
    uint32_t timeout = SPI_TIMEOUT;

    // Wait for transmit buffer to become empty
    while (!(DS1722_SPI->SR & SPI_SR_TXE))
    {
        if (--timeout == 0U)
            return false;
    }

    // Transmit one byte
    *(__IO uint8_t *)&DS1722_SPI->DR = tx_data;

    timeout = SPI_TIMEOUT;

    // Wait for received byte
    while (!(DS1722_SPI->SR & SPI_SR_RXNE))
    {
        if (--timeout == 0U)
            return false;
    }

    // Read received byte
    *rx_data = *(__IO uint8_t *)&DS1722_SPI->DR;

    return true;
}


// =============================================
// DS1722 CONFIGURATION
// =============================================

bool DS1722_Init(void)
{
    uint8_t dummy;

    // Enable communication
    DS1722_CE_HIGH();
    DS1722_Delay();

    // Write configuration register
    // Address 0x80 = write configuration register
    if (!DS1722_SPI_Transfer(DS1722_WRITE_CONFIG, &dummy))
    {
        DS1722_CE_LOW();
        return false;
    }

    // Set 12-bit resolution and continuous conversion
    if (!DS1722_SPI_Transfer(DS1722_CONFIG_12BIT, &dummy))
    {
        DS1722_CE_LOW();
        return false;
    }

    // Wait for last SPI transfer to finish
    while (DS1722_SPI->SR & SPI_SR_BSY);

    DS1722_Delay();
    DS1722_CE_LOW();

    // Allow first 12-bit conversion to complete.
    // Maximum conversion time is 1.2 seconds.
    return true;
}


// =============================================
// READ TEMPERATURE
// =============================================

bool DS1722_ReadTemperature(float *temperature)
{
    uint8_t dummy;
    uint8_t temp_lsb;
    uint8_t temp_msb;

    if (temperature == 0)
        return false;

    // Start SPI transaction
    DS1722_CE_HIGH();
    DS1722_Delay();

    // Send temperature LSB read address
    if (!DS1722_SPI_Transfer(
            DS1722_READ_TEMP_LSB, &dummy))
    {
        DS1722_CE_LOW();
        return false;
    }

    // Read temperature LSB
    // Sending dummy bytes generates the SPI clock
    if (!DS1722_SPI_Transfer(0xFFU, &temp_lsb))
    {
        DS1722_CE_LOW();
        return false;
    }

    // Read temperature MSB
    // DS1722 automatically increments register address
    if (!DS1722_SPI_Transfer(0xFFU, &temp_msb))
    {
        DS1722_CE_LOW();
        return false;
    }

    // Wait until SPI transmission is complete
    uint32_t timeout = SPI_TIMEOUT;

    while (DS1722_SPI->SR & SPI_SR_BSY)
    {
        if (--timeout == 0U)
        {
            DS1722_CE_LOW();
            return false;
        }
    }

    // End SPI transaction
    DS1722_Delay();
    DS1722_CE_LOW();

    // Combine temperature bytes
    // DS1722 uses 16-bit two's complement format
    int16_t raw_temperature =
        (int16_t)(((uint16_t)temp_msb << 8U) | temp_lsb);

    // Convert to degrees Celsius
    // 1 LSB = 1/256 degrees Celsius
    *temperature = (float)raw_temperature / 256.0f;

    return true;
}
